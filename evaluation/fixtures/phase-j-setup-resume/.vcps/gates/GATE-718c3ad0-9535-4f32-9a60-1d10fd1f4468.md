## Gate 4 — Verification

fresh Agent session (no shared context) independently re-ran
`test_payment_signature_and_idempotency` and
`test_forged_or_cross_tenant_webhook_is_rejected` for real (both `PASS`)
and, from its own reading of the code against `AC-1` alone (not told any
prior conclusion), confirmed: `hmac.compare_digest` is used (constant-time,
`VCPS-G4-005`-relevant since this checks the actual mechanism, not a
process exit code); the payload identity check binds the signed claim to
the caller's actual `tenant_id`/`order_id`/`event_id` (object-level, not
merely "a valid signature exists"); a replayed identical event is rejected
via the `event_id`/`status` check before mutation; no exception is
silently swallowed and no cross-tenant read is possible. This is real,
adversarial, `I2`-independent evidence that `AC-1` is satisfied by the
code as it stands (`VCPS-G4-001`/`003`/`004`/`005` genuinely met).

**Why this still cannot `PASS` or `PARTIAL`:** `standard/levels.md` §2's
table requires `E3 CI` fidelity for invariant assertions on an `R3`
change at `L3` (`INV-001`/`INV-002` are exactly such invariants). No
hosted CI exists (`FND-5ed8b1b2-2b5a-41f0-8df1-94287d034ec2`, `HIGH`
severity, `OPEN`) -- all evidence here is `E2 LOCAL`
(`EVD-8e8bb3c0-...`). Per `standard/levels.md §5`, `HIGH` severity blocks
`PASS` at `L3`, and `VCPS-GATE-010` permits `PARTIAL` progression past a
`MEDIUM`+-severity gap at `L3` only with an explicit `HC-08` decision
*before* proceeding -- no such decision exists for this finding. An
agent cannot grant itself that checkpoint (`VCPS-LC-003`-style
self-certification prohibition applied here).

`BLOCKED` (`EVIDENCE`: evidence exists but at `E2 LOCAL`, below the
`E3 CI` tier `levels.md` requires for `R3` invariant assertions at `L3`;
`DECISION`: an `HC-08` risk-acceptance decision for `FND-5ed8b1b2` is a
prerequisite to progress past this gate even at `PARTIAL`, and none has
been made). This blocks on the project's own standing evidence-
infrastructure gap, not on any defect found in `settle_payment` itself --
the independent review found none.
