## Gate 2 — Architecture

Reviewed as a distinct, disclosed phase from Gate 1's product review
(`independence.md VCPS-IND-005`, `I1` — required minimum at `L3`/`R3`
is `I1`, `levels.md §4`); same identity, explicit phase switch.

**Trust boundaries (VCPS-G2-011):** The payment webhook payload is
untrusted input. `settle_payment` treats it as such: `sign_payload` +
`hmac.compare_digest` verify the signature before anything else, and
the payload's claimed `tenant_id`/`order_id`/`event_id` are checked for
exact identity against the caller's own arguments (`payload != {...}`)
before any state is read or mutated — the signature alone does not
grant trust in the payload's claimed identity. Verification method
named: the existing `test_forged_or_cross_tenant_webhook_is_rejected`
test.

**Critical state engineering (VCPS-G2-010), authoritative state = order
status/payment_events/invoice (D1/D2):**
- *Authorization:* a valid HMAC signature against the shared secret.
- *Isolation:* tenant-scoped lookup via `(tenant_id, order_id)` composite
  key; cross-tenant payload identity mismatch is rejected.
- *Atomicity:* the whole check-and-mutate sequence runs inside
  `store.lock`.
- *Idempotency/concurrency:* `event_id` tracked in `order.payment_events`;
  a repeated event raises `Conflict` before any further mutation.
  Verification method named for all four: the existing
  `test_payment_signature_and_idempotency` test.
- *Observability:* **not addressed** — no audit log of settlement
  attempts, successes, or rejections.
- *Recovery:* **not addressed** — no documented procedure for detecting
  or correcting a settlement later found to be wrong.

**Failure design (VCPS-G2-012):** Failure modes (`InvalidWebhook`,
`NotFound`, `Conflict`) are enumerated via the three raised exception
types; this is not a migration/destructive/external-transaction
operation requiring a forward/rollback plan under this rule's narrower
trigger.

**Privileged AI actions (VCPS-G2-014):** not applicable — no AI-initiated
action is involved.

`PARTIAL`: four of six `VCPS-G2-010` properties are addressed with a
named verification method; observability and recovery are not, recorded
as `FND-1cfb269e` (`LOW`, does not itself violate a critical invariant,
so no `HC-08` is required to progress past this gate at `L3`,
`VCPS-GATE-010`).
