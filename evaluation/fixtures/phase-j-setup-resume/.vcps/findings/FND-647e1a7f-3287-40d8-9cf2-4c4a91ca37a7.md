## Untested non-PENDING cancellation guard

`cancel_order` (`commerce/admin.py`) rejects cancelling a non-`PENDING`
order (e.g. one already `PAID`) via a `ValueError`, raised before the
stock-restoration loop runs -- by inspection, this prevents a paid
order's reserved stock from being incorrectly restored a second time
(which would let the same inventory be oversold). No test in
`tests/test_commerce.py` actually exercises this path; the only existing
`admin.py` test (`test_role_required_and_cancel_restores_reserved_stock`)
cancels a `PENDING` order.

Rated `LOW`: static reading supports the guard is correctly ordered, and
this is a synthetic, non-production fixture; a real production use of
this code would need an executed test before relying on this path.
