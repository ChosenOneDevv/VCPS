## No audit trail or recovery procedure for payment settlement

`settle_payment` (`commerce/payments.py`) correctly engineers
authorization (HMAC signature), isolation (tenant-scoped order lookup,
payload identity binding preventing cross-tenant forgery), atomicity
(the whole check-and-mutate sequence runs under `store.lock`), and
idempotency (`event_id` tracked in `order.payment_events`, duplicate
events rejected with `Conflict`) — all four confirmed by a genuinely
independent fresh-session review (different session, no exposure to
this finding's own reasoning, which reran the test for real and verified
`hmac.compare_digest` specifically).

What is missing: no log/audit record is written when a settlement
succeeds, is rejected, or is attempted with an invalid signature, and no
procedure is documented for detecting or correcting a settlement later
found to be wrong (`VCPS-G2-010`'s "observability" and "recovery"
properties). Rated `LOW`, not `MEDIUM`+, because this is a gap in
documentation/instrumentation around an otherwise-correctly-engineered
control, not a defect in the control itself, and this is explicitly a
non-production synthetic fixture. A real production deployment of this
code would need to close this before relying on it for incident response.
