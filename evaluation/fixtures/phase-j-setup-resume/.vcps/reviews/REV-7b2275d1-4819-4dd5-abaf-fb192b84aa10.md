## Review: order creation and cancellation

**Intended behavior** (reconstructed from `INV-001`/`INV-002` and the
existing tests): orders and products are strictly tenant-scoped; stock
reservation on order creation is all-or-nothing across every line, even
when multiple lines target the same SKU; only a `tenant_admin` or
`platform_admin` may cancel an order, and only while it is still
`PENDING`, with stock correctly restored exactly once.

**Actual behavior found:** matches intent throughout, confirmed by a
real test run (8/8 `PASS`, `EVD-8e8bb3c0-5335-4a30-9458-f21f432fea10`) and
direct code reading. `create_order` validates every requested product and
aggregate stock sufficiency *before* decrementing any stock (confirmed
by `test_order_reservation_is_all_or_nothing`); the duplicate-SKU
aggregation fix (`BUG-00000000-0000-4000-8000-000000000002`) is in place
and unaffected by this review's own scope. `cancel_order` checks the
actor's role and the order's tenant-scoped existence before mutating
anything, and rejects a non-`PENDING` order before its stock-restore
loop runs -- correct by inspection, but genuinely untested (see
`FND-647e1a7f-...`).

**No DEFECT found** in this review's scope. One `EVIDENCE_GAP` remains
`OPEN`: the non-`PENDING` cancellation rejection path's lack of executed
test coverage. Per `workflows/review.md`'s exit condition, this scope is
reported `PARTIALLY REVIEWED` because of that open gap, not as "clean"
or "fully verified".
