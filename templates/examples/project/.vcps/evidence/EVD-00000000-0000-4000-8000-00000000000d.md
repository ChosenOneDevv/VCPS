## Regression evidence for the sync timestamp-tiebreak defect

Before the fix, two devices completing a sync request within the same
second resolved the tiebreak by device-registration order rather than by
preferring a `done: true` write, so a device that still had the item
marked incomplete could win and silently revert it. The fix changes the
tiebreak to prefer `done: true` whenever both writes share a timestamp.
This evidence reproduces the exact colliding-timestamp scenario and
confirms the completed state now survives it.
